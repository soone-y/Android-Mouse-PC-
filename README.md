# Sensor Mouse Lab — Revamp (v10)

スマートフォンの3軸比力・ジャイロセンサーから、重力方向を追跡してXY変位を検証するブラウザアプリです。**変位を保証する製品ではなく、実測とアルゴリズムを比較する検証版です。** v9相当のテキストソースから構成を見直して作成しました。JS/CSS/HTMLは分離しています。

## 使い方

1. このフォルダーをHTTPSの静的ホスティング（Cloudflare Pagesなど）に配置します。PC上の `localhost` で画面と模擬入力を確認する場合は `python -m http.server 8000` などを実行します。Android端末からPCの通常HTTPアドレスへのアクセスではセンサーが使えないことがあります。
2. スマホのブラウザでHTTPSページを開き、「センサー開始」を押します。必要ならモーションセンサー権限を許可します。
3. スマホを動かさず「静止校正（1.5秒）」を実行します。水平である必要はありません。校正失敗時は設置を安定させてやり直します。
4. 少し動かして再び静止させます。**OS線形加速度**（初期選択）、独自補正、初期重力固定を比較します。純粋積分とZUPT付き積分を切り替えて確認できます。
5. 必要に応じて記録をJSON/CSVに保存し、再計算・診断します。センサーがないPCでは「模擬データで検証」を使います。

## 見直した計算

- 比力 `raw` と端末角速度 `gyro` を `DeviceMotionEvent` から取得。ジャイロの角速度（beta, gamma, alpha）は度毎秒からrad/sへ変換。
- 静止校正で3軸比力から重力方向・大きさを推定し、初期角度の水平面（重力に垂直なXY）を固定。
- クォータニオンで角速度を積分し、最新姿勢から端末座標の重力ベクトルを予測。
- **初期姿勢との近さを静止判定に使わない**。直近300msの比力安定性、角速度、重力の大きさ、利用可能ならOS線形加速度を組み合わせる。
- 十分な静止候補が続いた場合、現在の重力方向で傾き誤差を速度制限付きで修正。以前のように「姿勢誤差が大きいほど補正が禁止される」閾値を使わない。
- 独自補正 `a_body = raw - predictedGravity` をその時点の姿勢で世界座標へ回転する。**初期のスマホ面へ再回転しない**。
- OS線形加速度はOS補正をそのまま採用し、同じ姿勢で世界座標に変換。独自補正と混合せず独立して積分。
- 比較用として、初期重力固定方式も維持。
- 3方式それぞれに**純粋積分**と**静止候補で速度ゼロ**の独立した積分器。加速度の偽デッドゾーン・摩擦・増幅率・隠れた平滑化を加えない。
- 計測時刻は `event.timeStamp` を優先し、利用不能なら `performance.now()`。120ms超の欠落時間は積分しない。
- 重力・予測傾斜誤差・静止判定・速度を別個に可視化・JSON/CSVへ記録。
- ユーザーが区間の開始・終了とも完全に停止したと確認できる場合、**ゼロ速度の境界条件**を使い「一定加速度バイアス」を区間内だけ逆算し、変位を再推定する実験機能を追加。

## 注意すべき物理的限界

- 3軸加速度と角速度だけでは、絶対位置、重力方向周りの絶対方位（ヨー）、静止と等速直線運動の区別は一般に不可能です。
- 「静止候補」の自動ZUPTは仮定に基づく操作です。等速運動中に速度をゼロにしてしまう場合があります。必ず純粋積分と比較してください。
- 正負対称の偶然誤差でも二重積分ドリフトは残ります。特に、姿勢推定が一時的に数度ずれるだけで約0.1〜0.5m/s²の偽加速度が生じ得ます。
- OSの線形加速度にもフィルター遅延・バイアスがあり、外部測位の代替にはなりません。初期姿勢の静止校正だけで加速度計の全軸バイアスを識別することもできません。
- センサーが動作するHTTPSサイトでもブラウザ・端末によって `acceleration` や `rotationRate` が取得できない可能性があります。自動で不完全な入力に切り替えず、欠損があれば明示します。
- 高精度なマウスポインターを目指す場合は、カメラ等による外部位置基準や接地運動の制約を検討してください。

## 動作検証

`node --test tests/*.test.mjs` （または `npm test`）で、初期傾斜・傾けたまま静止・静止時の姿勢誤差回復・加減速・ヨー回転後のXY移動・ゼロ速度区間補正・タイムスタンプ欠落・旧CSVパーサーを検証します。

既存CSVを再演算する場合は `node scripts/replay-log.mjs comparison.csv` を使用できます。CSVの冒頭に1.5秒程度の静止データが必要です。v10 JSONには初期校正ベクトルが保存されるため、その条件は不要です。

### 過去の実測ログの再計算の一例

2026-10-27に共有された `comparison (1).csv` を読み直した結果、同記録のX軸終点は以下でした。**この値は実距離との比較ではなく、アルゴリズム間の比較です。**

| 経路 | 補正なし終点 | ZUPT付き終点 |
|---|---:|---:|
| 独自姿勢・重力補正 | 約9.12m | 約0.42m |
| OS線形加速度 | 約1.38m | 約0.065m |
| 初期重力固定 | 約0.80m | 約0.032m |

以前の独自方式が示した約20.73mという終点からは減っていますが、**補正なし独自方式の誤差は依然として大きい**ことが分かります。ZUPTは観測値そのものを正したわけではなく、静止候補で速度をゼロにする仮定によって累積を抑えています。実端末での反復測定が必要です。

## 構成

- `index.html`：画面
- `assets/style.css`：デザイン
- `src/math.js`：ベクトル・クォータニオン
- `src/orientation.js`：ジャイロ姿勢と重力に基づく傾き補正
- `src/stationary.js`：初期姿勢に依存しない静止候補検出
- `src/pipeline.js`：センサーデータ処理・3方式の重力補正
- `src/integration.js`：二重積分・ZUPT・区間境界補正
- `src/plot.js`：平面軌跡と時系列
- `src/recording.js`：記録、CSV、旧形式の再生
- `src/app.js`：UI・ブラウザイベント
- `tests/`：模擬物理テスト
- `scripts/replay-log.mjs`：ローカルでの再計算ツール
